> 日期：2026-08-19（更新）
> 状态：待发出（未动代码）
> 用途：确定 **QMT 客户端「只下单」方案**的可行性

> 背景变更：miniQMT 通道已不可用，改用 **QMT 客户端（内置 Python 3.6）**。最终决策为
> **QMT 只做下单动作，信号计算/数据全留自有 Linux 服务器**。

---

## 一、背景（供工程师了解场景）

1. **策略类型**：宽基指数 ETF 定投/减仓，**周频判断、低频交易**。买入信号基于指数 PE/PB 百分位与股债利差（FED），卖出基于 PE 百分位。
2. **信号数据源**：指数估值（PE/PB/百分位）来自**外部第三方（蛋卷）**，FED 需自算（中债10年/美债10年收益率）。这部分数据与信号计算**全部在自有 Linux 服务器完成**，QMT 不参与计算。
3. **交易标的**：12 只场内 ETF（详见下表）。
4. **下单特征**：单笔金额小（约 ¥500~3000），频率低（每标的最多每周 1 笔买入、每月 1 笔卖出），限价单。
5. **部署现状**：策略引擎跑在 **Linux 服务器**（Python 3.11 + pandas/parquet），已有一整套回测系统；另有 **Windows 轻量服务器（2 vCPU / 2GB）** 作为 QMT 客户端载体。

---

## 二、最终方案架构（QMT 只下单）

```
Linux (3.11, 现有引擎原样不动)
 ├─ 拉蛋卷 / 读 parquet / 算信号（策略B + 本金阈值）
 ├─ 生成买卖指令：{signal_id, code, side, qty, price}
 ├─ 新增两个 HTTP 接口：
 │   ① GET  /api/pending-orders   → 返回待执行指令
 │   ② POST /api/order-result     → 接收成交回报，记账
 └────────────────────────────────────────────────┘
                       ↕ HTTP（urllib，标准库自带）
 ┌────────────────────────────────────────────────┐
Windows (2vCPU 2GB)  QMT 客户端（内置 Python 3.6）
 └─ 一个极简内置策略：
     run_time 定时轮询 → GET ① → passorder 下单 → POST ②
     （只用 urllib + json + passorder，全标准库，不碰 pandas/parquet）
```

### QMT 端极简策略（示意）

```python
#coding:gbk
import urllib.request, json

class a(): pass
A = a()
A.done = set()   # 已处理的 signal_id

def init(C):
    C.run_time("poll", "30nSecond", "2026-01-01 09:00:00")

def poll(C):
    req = urllib.request.urlopen("http://<linux_ip>:8000/api/pending-orders")
    orders = json.loads(req.read())
    for o in orders:
        if o["signal_id"] in A.done:
            continue
        passorder(23 if o["side"]=="buy" else 24, 1101, o["acct"],
                  o["code"], 5, o["price"], o["qty"],
                  "策略B", 2, o["signal_id"], C)
        urllib.request.urlopen(urllib.request.Request(
            "http://<linux_ip>:8000/api/order-result",
            data=json.dumps({"signal_id": o["signal_id"], "status":"sent"}).encode()))
        A.done.add(o["signal_id"])
```

### 幂等设计（防重复下单）

- 状态**由 Linux 权威维护**：订单表 `status: pending → executed`，QMT 只拿 `pending`。
- QMT 下单时在 `passorder` 的 **remark 里带 `signal_id`**。
- 下单前先 `get_trade_detail_data` 查当日委托/成交的 remark，**该 signal_id 已存在则跳过**（防「回报丢失但实际已下单」）。
- 每日收盘后**对账**：Linux 订单表 vs QMT 成交记录，不一致告警。
